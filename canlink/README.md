# CAN 工具（vdlink）

手机和电脑都能用的 CAN / CAN FD 工具，硬件用 **MKS CANable 2.0（Pro）**。方案和阶段见 issue #11，这里是阶段 1：看报文、录报文、发报文。

- 网页：<https://gcy2016.github.io/VehDiag_sef/canlink/>（源码在 `docs/canlink/`，直接发布，不用 build.py）
- 固件：`canlink/firmware/`（vdlink，在 CANable 2.0 开源 slcan 固件上改的，GPLv3）

## 怎么用

1. 用 **Chrome / Edge** 打开网页（UC、QQ、微信、小米自带浏览器不支持网页访问 USB）。安卓手机用 USB-C 公对公**数据线**（OTG）直连 CANable；电脑直接插 USB。iPhone 暂不支持（见 #11）。
2. 第一次用先到“设置 → 固件”刷 vdlink 固件（下面“刷固件”）。原版固件也能用，但时间戳是手机打的、采样点固定 88%、只听模式不生效。
3. 页签：**录制 / 查看 / 诊断 / 刷写 / 设置**（按 issue #12 的意见排的）。
   - **设置**：波特率、采样点、CAN FD、模式（只听 / 正常收发）、刷固件、演示模式、导出 / 导入设置。一般只设一次；通道开着时改了会自动重开通道（录制不中断）。
   - **录制**：连接设备、打开通道、开始录制、打标记都在这一页；打开通道不会自动录制，点“开始录制”时通道没开会自动打开；录制中下载 / 分享 / 查看置灰，停止后才能用；“总线状态”默认折叠。保存全部、两个标记之间、最后 N 秒或自定义时间段，下载或用手机分享菜单发出去。ASC 能直接用 CANalyzer 和 SEF 网站打开。
   - **查看 → 离线数据**：就是 GNL 通用版的数据分析（`docs/canlink/viewer/`）：自己加载 DBC、诊断问卷，打开 blf / asc，识别故障码、画曲线、报文提取、AI 助手。录制页点“查看”会把这段录制直接送过来。通道开着时会先提示关闭通道。
   - **查看 → 在线报文**：按 ID（每个 ID 一行，黄色是 1 秒内变化的字节）或滚动显示；可暂停、按 ID 过滤（`7E0,7E8`、`700-7FF`）。
   - **诊断**（阶段 2，通用 UDS）：先选 / 建**控制器**（名称、请求 ID、响应 ID、功能寻址 ID、是否 CAN FD、填充字节、29 位扩展帧），一份配置可有多个控制器，能导入导出；ID 等保密内容由用户自己填，不进仓库。下面是会话切换 / 复位 / 保持在线、安全访问（27，算法做成**可加载插件**，贴一段 JS 在本机运行，不进仓库）、读 / 清故障码（对照“离线数据”里加载的诊断问卷显示含义）、读 / 写数据（DID）、例程控制（31），以及常用指令（UDS 数据，经 ISO-TP 发出并解析应答）。多帧收发（ISO-TP：单帧 / 首帧 + 连续帧 / 流控 / 0x78 等待）都自动处理。“手动发送原始帧”折叠在最下面，用于非诊断报文和循环发送。
   - **刷写**（阶段 3，通用 UDS 刷写）：控制器和安全算法插件都用“诊断”页的。选 Driver / App 文件（S19 / Intel HEX / 原始 bin，bin 要填起始地址），填指纹诊断仪编号。刷写流程写成一份可编辑的步骤表（JSON，能导入导出、恢复默认）：扩展会话 → 安全访问 → 编程预处理 → 功能寻址关 DTC / 停收发（静默整车）→ 编程会话 → 安全访问 → 写指纹 → 刷 Driver（每段 34/36/37 + 激活）→ 刷 App（每段擦除 + 34/36/37）→ 校验 → 复位 → 恢复通信 / DTC / 默认会话。换控制器 / 供应商改这份配置就行（步骤 op：req 物理请求 / func 功能寻址不等应答 / security / fingerprint / tp_on / tp_off / flash / delay）。有总进度条、分步状态和日志；中途失败会显示停在哪步，并自动把整车其他控制器恢复过来。刷写前确认电压 / 充电宝、手机不锁屏。多帧按 ECU 流控（BS / STmin）分块发，不一次灌满。
4. 授权过一次的设备，下次打开网页或插上设备会自动连接。
5. **离线可用**：打开过一次后，网页文件存在本机（`sw.js`），没网、GitHub 打不开也能打开；有网时 3 秒内取到新版本就用新的。可在浏览器菜单里“添加到主屏幕 / 安装应用”。改了网页文件要把 `sw.js` 的 `VERSION` 加 1。
5. 设置和常用指令存在浏览器里，清理浏览器数据会丢；“设置 → 导出”备份一份。
6. 以后做安卓 APK：网页代码不用改，APK 用原生代码实现 USB 串口，注入 `window.VdlinkNative`（接口见 `docs/canlink/transport.js` 的 `NativeTransport`）。

## 刷固件

板子上 **BOOT** 两针用跳线帽短接，再插 USB，进入芯片自带的烧录模式（USB ID 0483:df11）。

- **安卓手机（推荐）**：网页“固件”页 → 刷入 → 选 STM32 BOOTLOADER → 等“完成”。
- **电脑**：Windows 上浏览器一般看不到烧录模式的设备（缺 WinUSB 驱动）。用 ST 官方 STM32CubeProgrammer，连 USB，把 `docs/canlink/fw/vdlink-1.0.bin` 写到 `0x08000000`。
- 刷完拔下、**取下跳线帽**、再插上。网页“连接”后显示“固件：vdlink 1.0”就对了。
- 想刷回原版：MKS 的仓库 makerbase-mks/CANable-MKS 里有原版 `.bin`，同样方法刷。

## vdlink 固件改了什么

| | 原版 slcan 固件 | vdlink 1.0 |
|---|---|---|
| CAN 时钟 | 170 MHz，常用波特率要凑 | 80 MHz（CAN 常用值），系统 160 MHz |
| 波特率 / 采样点 | 只有预设，采样点固定 88% | 网页随便设（命令 `xN` / `xD`） |
| 收发器延时补偿 | 没开，数据段快了发不出去 | 数据段 ≥1M 自动开 |
| 只听模式 `M1` | 设了不生效（开通道时被覆盖） | 修好了 |
| 时间戳 | 没有 | 中断里打微秒时间戳（`Z2`） |
| 收报文 | 主循环轮询，硬件只有 3 帧缓冲，忙时丢帧 | 中断收进 64 帧缓冲 |
| 发出去的报文 | 不回显 | 可回显（`xT1`，行首 `>`），录进 ASC 标 Tx |
| 时钟精度 | 板子没晶振，内部振荡器约 ±1% | 用 USB 帧（1 ms，来自电脑 / 手机的晶振）测误差，开通道前自动校准，剩余误差报给网页修正时间戳 |
| Bus Off | 不恢复 | 自动恢复 |
| USB 发送 | 每次 64 字节，队列满了会写坏 | 每次 512 字节，满了整行丢弃并计数 |

原版的命令（`O C Sx Yx Mx Ax V E t T r R d D b B`）全保留，cangaroo、slcand 照样能用。

### 新增命令（都以 `\r` 结尾）

| 命令 | 作用 | 回复 |
|---|---|---|
| `Z0` / `Z1` / `Z2` | 时间戳：关 / Lawicel 4 位毫秒 / 8 位十六进制微秒（加在数据后面） | 无 |
| `xI` | 固件信息 | `xIvdlink,1.0,80000000` |
| `xS` | 状态 | `xS开,只听,PSR,ECR,错误位,丢帧数,时钟ppm,校准完成,HSITRIM` |
| `xN<分频>,<tseg1>,<tseg2>,<sjw>` | 仲裁段位时间（十进制，tq 个数） | `\r` 成功 / `\a` 失败 |
| `xD<分频>,<tseg1>,<tseg2>,<sjw>` | 数据段位时间 | 同上 |
| `xO0` / `xO1` | ISO / 非 ISO CAN FD | 同上 |
| `xT0` / `xT1` | 回显发出去的报文（行首加 `>`） | 同上 |

位时间：波特率 = 80 MHz ÷ 分频 ÷ (1 + tseg1 + tseg2)，采样点 = (1 + tseg1) ÷ (1 + tseg1 + tseg2)。设置命令要在通道关闭时发。

### 编译

```sh
sudo apt-get install gcc-arm-none-eabi libnewlib-arm-none-eabi
canlink/firmware/build.sh        # 自动下载原版仓库（只用它的 ST 驱动库），输出 build/vdlink-1.0.bin
```

改了固件后把 `build/vdlink-1.0.bin` 复制到 `docs/canlink/fw/`，版本号改 `Makefile` 的 `FW_VERSION`（网页里的文件名也要跟着改）。

## 自测

```sh
node canlink/test/test_web.js    # 位时间、slcan 解析、录制 → ASC → 用 SEF 的读取代码读回核对
node canlink/test/test_dfu.js    # 模拟 STM32 烧录模式，检查刷固件流程
node canlink/test/test_diag.js   # 诊断：组帧、故障码解析、安全算法插件、ISO-TP 与模拟 ECU 往返
node canlink/test/test_flashfile.js  # 刷写文件解析：S19 / Intel HEX / bin
node canlink/test/test_flash.js  # 刷写流程：对着模拟 ECU 跑完整刷写、流控分块、失败恢复
```

## 到货后的台架验证（还没做）

硬件到手前，固件只编译过、没在板子上跑过。到货后按这个顺序验：

1. 刷 vdlink，网页连接后显示固件版本；“状态”里板子时钟误差几秒内变成“±几百 ppm”（不再显示“校准中”）。
2. 台架上 CANalyzer + Vector 接口发报文（500k / 2M FD、500k / 5M FD 各一遍），CANable 只听，两边同时录，对比帧数、内容和时间间隔。
3. 切正常收发，从网页发普通帧和 FD + BRS 帧，CANalyzer 能收到；网页里显示“→”回显。
4. 高负载（总线 60% 以上）录 10 分钟，看“丢帧”是不是 0。
5. 手机上录 10 分钟，看是否掉线、屏幕是否保持常亮。
